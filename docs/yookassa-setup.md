# ЮKassa (Яндекс): от регистрации до полей в админке WL Sales

Пошаговая шпаргалка для нового аккаунта. Сайт проекта: `https://white-list.space`  
Админка шлюзов: `/admin/payments/gateways`  
Webhook проекта: `https://white-list.space/webhooks/yookassa`

---

## 0. Что куда в итоге (кратко)

| Где взять в ЮKassa | Куда вставить в WL Sales |
|---|---|
| **shopId** (Настройки → Магазин) | Платёжные системы → **ЮKassa** → поле **shopId** |
| **Секретный ключ** (Интеграция → Ключи API) | то же → **secretKey** |
| URL возврата после оплаты | то же → **Return URL** = `https://white-list.space/account/orders` |
| HTTP-уведомления | в кабинете ЮKassa URL = `https://white-list.space/webhooks/yookassa` |
| Тестовый магазин | в карточке шлюза включить **Тест** (`test_mode`) |
| Боевой магазин | **Тест** выключить, ключи взять от боевого магазина |

Дополнительно (почта Яндекса, не платежи): `/admin/mail` — SMTP `smtp.yandex.ru` (см. §7).

## 1. Регистрация в ЮKassa

1. Откройте [https://yookassa.ru](https://yookassa.ru) → **Подключить ЮKassa** / регистрация.
2. Войдите через аккаунт Яндекса (или создайте новый).
3. Выберите сценарий:
   - **Быстрый тест без договора** — тестовый магазин (для проверки сайта). Данные компании можно не заполнять сразу.
   - **Боевые платежи** — юрлицо / ИП: анкета организации → проверка → договор (ЭЦП или бумажный).

Пока договор не подписан и магазин не «зелёный», на сайте оставляйте только **тестовый** магазин и флаг **Тест** в админке.

Официальные гайды:
- [Подключение платежей](https://yookassa.ru/docs/support/merchant/payments/implement/overview)
- [Быстрый старт API](https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start)
- [Ключи](https://yookassa.ru/docs/support/merchant/payments/implement/keys)
- [HTTP-уведомления](https://yookassa.ru/developers/using-api/webhooks)

## 2. Создать / выбрать магазин

В личном кабинете ЮKassa:

1. Создайте **тестовый магазин** (для отладки) и позже — **боевой**.
2. Укажите сайт: `https://white-list.space`
3. Способ подключения: **API** (HTTP Basic Auth) — не старый «HTTP-протокол CMS».

У магазина есть свой **shopId** и свои ключи. Не смешивайте ключи тестового и боевого магазина.

---

## 3. Где взять shopId и secretKey

### shopId
**Настройки → Магазин** (или карточка магазина) → поле **shopId** / идентификатор магазина.  
Это число (или строка цифр). Копируйте целиком.

### secretKey
**Интеграция → Ключи API** → создать / скопировать **секретный ключ**.

- Для **тестового** магазина ключ обычно виден сразу в кабинете.
- Для **боевого** — сгенерировать, подтвердить SMS, **скачать и сохранить**: повторно целиком не показывают.

Ключ вставляется в админку **один раз**. Поле в форме секрета: если уже сохранено, показывается `********` — пустое поле при сохранении **не затирает** старый ключ.

## 4. HTTP-уведомления (webhook) — обязательно

Без этого заказ после оплаты на сайте **не перейдёт в «Оплачен»** (клиент вернётся на сайт, а статус останется «ожидает»).

В кабинете ЮKassa: **Интеграция → HTTP-уведомления**

| Параметр | Значение |
|---|---|
| URL | `https://white-list.space/webhooks/yookassa` |
| Протокол | только **HTTPS**, порт 443 |
| События | минимум **`payment.succeeded`** (можно добавить `payment.waiting_for_capture`, `payment.canceled` — проект обрабатывает успех) |

Проверка: после тестовой оплаты в админке WL Sales заказ должен стать **paid** / дальше по сценарию выдачи. Если нет — смотрите `storage/logs/app.log` и ответ webhook (должен быть HTTP 200).

Поле **Webhook secret** в нашей админке для ЮKassa **опционально** (подпись в текущей интеграции не обязательна) — можно оставить пустым.

## 5. Куда вставлять в админку проекта

1. Войти: `https://white-list.space/admin`
2. Меню → **Платёжные системы** → `/admin/payments/gateways`
3. В фильтре **Тип** выбрать **Legacy (ЮKassa и др.)** — иначе строка `yookassa` в списке скрыта.
4. Открыть **ЮKassa** (код `yookassa`).

Заполнить:

| Поле в форме | Что вставить |
|---|---|
| **Название** | ЮKassa (можно не менять) |
| **Включён** | да |
| **Тест** | да — тестовый магазин; нет — боевой |
| **Мин. сумма ₽** | 0 или свой порог |
| **shopId** | из Настройки → Магазин |
| **secretKey** | из Интеграция → Ключи API |
| **Return URL** | `https://white-list.space/account/orders` |
| **Доп. комиссия %** | 0 (или наценка, если нужна) |

Сохранить → на чекауте должен появиться способ «Карта / СБП через ЮKassa».

### Fallback в `.env` (не обязательно, если заполнено в админке)

Админка / таблица `payment_gateways` имеет приоритет. `.env` — запасной вариант:

```env
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=...
YOOKASSA_RETURN_URL=https://white-list.space/account/orders
```

Старые ключи в `settings` (`pay_yookassa_*`) при первом сиде могут подтянуться в шлюз автоматически — дальше править только карточку шлюза.

## 6. Проверка «с нуля»

1. В ЮKassa — тестовый магазин + ключи + webhook URL.
2. В админке — Legacy → ЮKassa → shopId / secretKey / Return URL, **Вкл** + **Тест**.
3. На витрине создать заказ → Оплата → выбрать ЮKassa → тестовая карта из [документации ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).
4. Вернуться на сайт → в `/admin/orders` статус **Оплачен** (после webhook).
5. Перед боем: выпустить ключи боевого магазина, выключить **Тест**, обновить shopId/secretKey, webhook тот же URL.

---

## 7. Почта на Яндексе (опционально, для тикетов)

Если письма клиентам идут через Яндекс.Почту / 360:

1. Создать ящик (например `noreply@ваш-домен` или `@yandex.ru`).
2. Включить доступ для почтовых программ / пароль приложения (если включена 2FA).
3. Админка → **Почта (SMTP)** → `/admin/mail`:

| Поле | Значение |
|---|---|
| Включить SMTP | да |
| Host | `smtp.yandex.ru` |
| Port | `465` (ssl) или `587` (tls) |
| Encryption | `ssl` для 465 / `tls` для 587 |
| Username | полный email |
| Password | пароль ящика или пароль приложения |
| From email | тот же email |
| From name | `WL Sales` |

Сохранить → «Отправить тест».

## 8. Типичные ошибки

| Симптом | Что проверить |
|---|---|
| ЮKassa нет в списке шлюзов | Фильтр **Тип = Legacy** |
| На оплате нет ЮKassa | **Включён**, заполнены shopId и secretKey, мин. сумма ≤ суммы заказа |
| 401 / «не удалось создать платёж» | Перепутаны тест/бой ключи; пробелы в ключах; неверный shopId |
| Оплатил, заказ висит | Webhook URL и событие `payment.succeeded`; HTTPS доступен снаружи |
| Секрет «пропал» после сохранения | Нормально (`********`); новый ключ вставлять только при смене |
